# AI-Powered Document Question Answering System (RAG)

Upload a PDF, ask questions about it, and get answers generated by an LLM from the
relevant passages of the document, with the source page shown next to each answer.

> **Status: Day 1 of 5 complete.** The document ingestion pipeline (PDF loading, text
> cleaning, chunking) is built and tested. Embeddings, the vector database, LLM
> integration and the React interface are planned for the following days (see
> [Roadmap](#roadmap)).

## How it works (target architecture)

```
          INGESTION (offline, once per document)
 PDF ──► load text ──► clean ──► chunk ──► embed ──► vector store
         (Day 1)       (Day 1)   (Day 1)   (Day 2)    (Day 2)

          QUERY (online, once per question)
 question ──► embed ──► similarity search ──► top-k chunks ──► prompt + LLM ──► answer
                          (Day 3)                               (Day 3)        + sources
```

Why RAG instead of asking the LLM directly? A model only knows its training data and
may invent details. RAG first retrieves the passages of *your* document that relate to the
question and hands only those to the model, so answers are grounded in the document and can
be traced back to a page.

## What is implemented so far

| Module | Responsibility |
| --- | --- |
| `src/rag/loader.py` | Extracts text per page from a PDF with `pypdf`; clear errors for corrupt, password-protected and scanned (no text) files |
| `src/rag/preprocess.py` | Cleans extracted text (ligatures, hyphenated line breaks, wrapped lines, control characters) and removes repeated headers/footers |
| `src/rag/chunker.py` | Recursive character chunking with configurable size and overlap; chunks never cross pages so every chunk has an exact page citation |
| `src/rag/ingest.py` | Ties the steps together: `ingest_pdf(path)` returns source-tagged chunks; also provides a command line preview |
| `src/rag/models.py`, `errors.py` | Data classes (`PageText`, `Chunk`) and project-specific exceptions |

## Setup

Requires Python 3.10 or newer.

```bash
git clone <this repository>
cd rag-document-qa

python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

pip install -r requirements-dev.txt  # runtime (pypdf) + test tools (pytest, reportlab)
```

## Usage

Preview how a PDF is split into chunks:

```bash
PYTHONPATH=src python -m rag path/to/file.pdf --chunk-size 800 --overlap 150 --show 3
```

Example output:

```
file.pdf: 15 chunks from 3 page(s)
  [file-p1-c0] page 1, 365 chars: Retrieval-augmented generation combines a search step...
```

Use it from Python:

```python
from rag.ingest import ingest_pdf

chunks = ingest_pdf("report.pdf", chunk_size=800, overlap=150)
for chunk in chunks[:2]:
    print(chunk.chunk_id, chunk.page, chunk.text[:80])
```

### Choosing chunk size and overlap

| Setting | Too small | Too large |
| --- | --- | --- |
| `chunk_size` | Chunks lose the context needed to answer | A chunk mixes several topics, so its embedding matches none of them well |
| `overlap` | An answer split across a boundary is cut in half | Near-duplicate chunks waste storage and crowd out other results |

The defaults (800 / 150 characters) are a starting point; later days compare settings
using retrieval results.

## Known limitations

- Scanned PDFs (images of text) are rejected with a clear error; OCR is not supported.
- Tables and multi-column layouts are extracted in reading order by `pypdf`, which can
  interleave columns.
- Header/footer removal only looks at the top and bottom two lines of each page and needs
  at least three pages.
