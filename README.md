# AI-Powered Document Question Answering System (RAG)

Upload a PDF, ask questions about it, and get answers generated by an LLM from the
relevant passages of the document, with the source page shown next to each answer.

> **Status: Day 2 of 5 complete.** PDF ingestion (Day 1) and embeddings plus vector search
> (Day 2) are built and tested: given a question, the system finds the most relevant passages
> and their pages. LLM answers, the API and the React interface are planned for the following
> days (see [Roadmap](#roadmap)).

## How it works (target architecture)

```
          INGESTION (offline, once per document)
 PDF ──► load text ──► clean ──► chunk ──► embed ──► vector store
         (Day 1)       (Day 1)   (Day 1)   (Day 2)    (Day 2)

          QUERY (online, once per question)
 question ──► embed ──► similarity search ──► top-k chunks ──► prompt + LLM ──► answer
              (Day 2)       (Day 2)                            (Day 3)        + sources
```

Why RAG instead of asking the LLM directly? A model only knows its training data and
may invent details. RAG first retrieves the passages of *your* document that relate to the
question and hands only those to the model, so answers are grounded in the document and can
be traced back to a page.

## What is implemented so far

| Module | Responsibility |
| --- | --- |
| `src/rag/loader.py` | Extracts text per page from a PDF with `pypdf`; clear errors for corrupt, password-protected and scanned (no text) files |
| `src/rag/preprocess.py` | Cleans extracted text (ligatures, hyphenated line breaks, wrapped lines, control characters) and removes repeated headers/footers |
| `src/rag/chunker.py` | Recursive character chunking with configurable size and overlap; chunks never cross pages so every chunk has an exact page citation |
| `src/rag/ingest.py` | `ingest_pdf(path)`: load, clean and chunk a PDF; command line preview |
| `src/rag/embeddings.py` | `SentenceTransformerEmbedder` (neural model, default `all-MiniLM-L6-v2`) and `HashingEmbedder` (offline word-overlap baseline), behind one small interface |
| `src/rag/vectorstore.py` | `VectorStore`: exact cosine-similarity search, `min_score` cutoff, replace-by-file, save/load to disk |
| `src/rag/faiss_store.py` | `FaissVectorStore`: the same interface on a FAISS flat index |
| `src/rag/retriever.py` | `Retriever`: index PDFs and search them with a question; refuses an index built with a different embedder |
| `src/rag/query.py` | Command line to try retrieval on a PDF |
| `src/rag/models.py`, `errors.py` | Data classes (`PageText`, `Chunk`) and project-specific exceptions |

## Setup

Requires Python 3.10 or newer.

```bash
git clone https://github.com/sowmyakasu047-stack/rag-document-qa.git
cd rag-document-qa

python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

pip install -r requirements-dev.txt  # runtime + test tools
```

The first run with the neural embedder downloads the model (about 90 MB) and caches it.
Installing `sentence-transformers` also installs PyTorch, which is a large download.

## Usage

### Preview chunking (Day 1)

```bash
PYTHONPATH=src python -m rag path/to/file.pdf --chunk-size 800 --overlap 150 --show 3
```

### Find the passages that answer a question (Day 2)

```bash
# Neural embeddings (recommended)
PYTHONPATH=src python -m rag.query path/to/file.pdf "What is chunking?" --k 3 --embedder minilm

# Offline word-overlap baseline (no download, matches shared words only)
PYTHONPATH=src python -m rag.query path/to/file.pdf "What is chunking?" --k 3
```

Example output:

```
Indexed 3 chunks from file.pdf with 'hashing-512'.
1. score 0.408 | page 1 | Photosynthesis is the process by which plants convert sunlight...
```

### From Python

```python
from rag import Retriever, SentenceTransformerEmbedder

retriever = Retriever(SentenceTransformerEmbedder())
retriever.add_pdf("report.pdf")                    # re-adding the same file name replaces it
for hit in retriever.search("What were the main findings?", k=3, min_score=0.3):
    print(f"{hit.score:.2f}  {hit.chunk.source} p.{hit.chunk.page}  {hit.chunk.text[:80]}")

retriever.save("index/")                           # later: Retriever.load("index/", embedder)
```

To use FAISS instead of the NumPy store:

```python
from rag.faiss_store import FaissVectorStore
retriever = Retriever(embedder, FaissVectorStore(embedder.dimension, embedder.name))
```

### Choosing chunk size, overlap, k and min_score

| Setting | Too small | Too large |
| --- | --- | --- |
| `chunk_size` | Chunks lose the context needed to answer | A chunk mixes several topics, so its vector matches none of them well |
| `overlap` | An answer split across a boundary is cut in half | Near-duplicate chunks waste space and crowd out other results |
| `k` | The answer may be in chunk k+1 | The LLM prompt fills with noise |
| `min_score` | Irrelevant passages are returned | Valid passages are dropped |

Search always returns the nearest chunks, even when none is relevant, so `min_score` is what
lets the system say "not found in the document". Its best value depends on the embedder and is
tuned in later days.

## Known limitations

- Scanned PDFs (images of text) are rejected with a clear error; OCR is not supported.
- Tables and multi-column layouts are extracted in reading order by `pypdf`, which can
  interleave columns.
- Header/footer removal only looks at the top and bottom two lines of each page and needs
  at least three pages.
- `HashingEmbedder` matches shared words only and has occasional hash collisions; it is a
  baseline for offline use and tests, not a replacement for the neural embedder.
- The neural embedder and the FAISS store were written without network access and have not
  yet been run against the real libraries (see `docs/day-02-notes.md`).
